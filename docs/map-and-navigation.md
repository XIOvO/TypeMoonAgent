# 地图与导航设计 V1

## 目标

为玩家移动、NPC 跨地点接近、剧情召集和未来地图 UI 提供同一套空间事实与路线查询。地图系统必须能表达“能否到达、为什么不能到达、需要经过哪里、预计花费什么”，同时不取得改变世界的权力。

## 当前基线与问题

当前 `GameState.locations` 仅保存地点 ID 与 `exits`，`nextStepToward()` 在该出口图上做 BFS。这是可靠的最小实现，已用于相邻移动与跨地点接近；但它无法表达区域层级、单向通道、门锁、封锁、路线成本、传送或玩家探索状态。

因此，当前实现被定义为**临时空间适配层**，而不是公开的正式地图协议。业务代码不得把 `locations.exits` 当作长期地图 API。

## 领域模型

```text
MapTopology（静态、版本化）
  MapNode：世界 / 区域 / 楼层 / 场景 / 房间等层级节点
  MapEdge：连接方向、移动方式、基础时间/成本、进入条件

WorldMapState（动态、随存档变化）
  EdgeCondition：开放、封锁、门锁、损坏、剧情临时通路
  NodeCondition：危险、禁入、临时事件、可见性限制
  Exploration：玩家或队伍已探索的节点/边

Navigation Query（纯查询）
  reachable / nextStep / route / estimatedCost / blockedReasons
```

静态拓扑由地图内容包或地图插件配置提供，可独立版本化；动态变化属于 `world.state`，必须通过受控命令与事件确认。这样“冬木大桥被毁”“门被打开”“活动区域出现入口”都是可回放的世界变化，而不是运行时偷偷修改地图定义。

## 能力边界

| 能力 | 输入 | 输出 | 禁止事项 |
| --- | --- | --- | --- |
| `world.map` | 地图 ID、节点/边查询、已提交世界状态 | 节点、边、层级、当前通行条件 | 直接移动角色、写入封锁或探索状态 |
| `world.navigation` | 起点、终点、旅行策略、已提交世界状态 | 可达性、路线、下一步、成本、不可达原因 | 推进时间、选择剧情、修改角色位置 |
| `world.commandGateway` | 已验证的移动/剧情命令 | 已确认事件与新世界状态 | 让地图插件绕过规则写入 |

导航策略会显式区分普通行走、特殊移动、剧情召集与能力移动。特殊能力不是在地图层硬编码角色设定：它由命令或剧情插件提供授权上下文，导航只依据该授权计算可用边与成本。

## 关键行为

1. NPC 主动接近玩家：世界模拟读取已提交玩家位置，调用 `nextStep`；每次仅提交一条合法边的移动，抵达后才可发起同场互动。
2. 剧情召集：剧情插件请求路线或抵达条件；若可达则创建可重试任务，若被封锁则得到结构化原因并选择等待、改道或改为远程讯息。
3. 玩家移动：输入只是一项尝试。命令权威层用导航结果校验，再写入移动事件、角色位置与必要的时间成本。
4. 地图 UI：只消费玩家可见的节点、边和探索投影；不能读取隐藏 NPC、未探索地点或剧情封锁原因。

## 分阶段落地

### M1：兼容查询层（已完成）

已以现有 `locations/exits` 适配 `world.map` 与 `world.navigation` 的最小只读接口，保持原有排序 BFS、存档格式和跨地点接近的单步移动逻辑不变。导航结果已区分“无路径”“未知节点”“目标已抵达”。

### M2：正式拓扑与动态条件

引入节点/边标识、方向、基础成本与动态通行条件；将当前简单地点图迁移为首份地图内容包。移动仍必须通过命令权威层提交，动态条件以事件驱动更新。

### M3：投影与扩展规则

增加玩家地图投影、探索/迷雾、路线时间展示、区域层级与受授权的特殊移动。传送、飞行、魔术等能力通过导航策略与授权上下文接入，不破坏普通路线的确定性。

## 非目标

本设计阶段不实现地图 UI、美术地图、全球坐标、连续物理移动、完整旅行时间系统或所有特殊能力。也不把 NPC 的“想找玩家”写进地图层；那是世界模拟/剧情策略的决策，地图只回答其是否可行及如何到达。
