# 交付路线图与验收标准

## 阶段 0：基础约束

产物：核心契约、Runtime 规则、角色规范、仓库目录与自动校验。

验收：无论来自前端还是 Agent，任何状态修改都必须能追溯到 GameEvent；非法契约不能进入 Runtime。

## 阶段 1：单角色对话闭环

产物：Session、PlayerAction API、单角色 Observation、Agent Orchestrator、Event Stream、基础前端对话页。

验收：

- 玩家一句普通对话得到角色回应。
- 角色仅使用 Observation 中可知的信息。
- 模型输出无效、超时或服务不可用时，世界状态保持不变。
- 重复提交同一 action ID 不产生重复事件。

## 阶段 2：规则驱动行动

产物：地点、可达性、角色位置、移动与互动规则；状态 revision 和并发冲突策略。

验收：角色的移动请求必须由 Runtime 裁决；无效目的地、不可达路径和过期状态不会产生位置更新。

## 阶段 3：按需知识与记忆

产物：Knowledge / Memory 条目、权限标签、工具网关、检索审计、冷路径记忆生成。

验收：角色可回忆已发生的相关事件；不能访问未解锁 Lore、其他角色私密记忆或未来剧情。

## 阶段 4：持久化后台任务与按需世界推进

产物：事务内 Job / Outbox、记忆整合任务迁移、任务幂等与重试、最小 `WorldTick` / `SimulationJob`、角色筛选预算。

验收：进程重启或模型不可用不会丢失已确认事件触发的后台工作；世界推进只唤醒受影响角色；任何客观变化仍能追溯到 Runtime 确认的 `GameEvent`。

## 阶段 5：多角色与导演

产物：相关性调度、多角色冲突裁决、导演触发条件、后台世界推进。

验收：日常单人对话不因后台系统增加额外同步模型调用；多人冲突结果可重放、可解释。

## 阶段 6：运营与质量

产物：观测指标、回放工具、内容审核、成本与延迟告警、数据备份与迁移策略。

验收：能回答“本事件为何发生、角色为何知道、模型调用了什么工具、耗时和成本如何”。

## 每阶段通用完成条件

- 对新增数据契约编写序列化与反序列化测试。
- 对 Runtime 规则编写确定性单元测试。
- 对至少一个成功路径、拒绝路径、模型失败路径执行端到端测试。
- 不引入绕过 Event Log 或权限过滤的快捷写入。
