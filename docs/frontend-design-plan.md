# 前端整体设计方案（当前版）

> 状态说明：本文将需求分为“已确定”“已预留但尚未制作”和“待讨论”。
> 已确定的是当前项目的产品方向，不代表所有界面都已经实现。

## 1. 产品定位与体验目标

前端目标不是把 Agent 对话包装成聊天窗口，而是制作一个以 **Fate / FGO 风格视觉小说阅读体验** 为核心、带有轻度地图、档案、玩家能力和文字战斗表现的单人 Agent 游戏。

玩家的大部分时间应处于主叙事画面：观看背景和立绘、阅读剧情和对白，并在轮到自己时自然输入自由文本。地图、档案和数值信息是随时可打开的游戏层，不应长期遮挡叙事。

```text
Runtime 确认的 GameEvent / GameState
              ↓
未来的 Narrative Renderer
              ↓
NarrativeBeat（播放计划）
              ↓
主叙事页 / 地图 / 档案 / 玩家面板 / 战斗面板
```

前端只展示已确认的世界事实和叙事播放计划；它不直接决定剧情结果、移动结果、HP 或角色状态。

## 2. 已确定：主叙事画面

### 2.1 总体形态

采用 **FGO 对话界面为主、FSN 叙事阅读为辅** 的混合形式。

```text
┌──────────────────────────────────────────────┐
│  返回地图／章节名                    菜单      │
│                                              │
│                场景背景                       │
│                                              │
│       左侧立绘            右侧立绘             │
│                                              │
│  ┌────────────────────────────────────────┐  │
│  │ 角色名                                  │  │
│  │ 对白、叙事或玩家输入区域                 │  │
│  │                                    LOG   │  │
│  └────────────────────────────────────────┘  │
│  地图   档案   玩家   记录                    │
└──────────────────────────────────────────────┘
```

- 场景以全屏或近全屏背景为主。
- 同屏通常展示 0–3 名角色立绘；初期主要支持左右站位，中间站位保留给关键镜头。
- 底部使用半透明深蓝黑文本框，以保证背景和立绘是视觉主体。
- 常用入口保持轻量图标或窄按钮；不常驻大面积侧栏或聊天面板。

### 2.2 两种阅读状态

| 状态 | 使用场景 | 视觉表现 |
| --- | --- | --- |
| 对话模式 | 角色发言、短说明、交互回应 | FGO 式角色名牌、立绘、较紧凑文本框。 |
| 叙事模式 | 环境描写、时间推进、镜头切换、内心独白 | 可隐藏名牌与立绘，让文本框扩展为更接近 FSN 的大面积阅读区域。 |

两种模式只是一份播放计划的不同展示，不代表两个不同的游戏系统。

### 2.3 玩家输入

不另开悬浮聊天窗。播放结束后，**同一个底部文本区域**转换为自由输入框：

```text
你想说什么，或做什么？
```

玩家可在同一输入中混合：

- 对角色说的话；
- 行动尝试；
- 观察、移动和物品使用；
- 明确标记或由模型识别的内心想法；
- 战斗指挥、委托同行者或明确快速结算请求。

输入文本不是直接世界事实。后端会解析为候选意图，Runtime 验证后再产生前端可见结果。玩家私密想法不会直接发送给 NPC，也不应显示在公共事件流中。

## 3. 已确定：场景播放与节奏

### 3.1 使用完整播放块，不使用模型 Token 直流

当前选择：模型或叙事层一次生成一个相对完整的场景回应，返回 **2–5 个播放块**；浏览器本地按块、按字播放。

```text
完整 NarrativeBeat
  ├─ narration：环境、动作、镜头过渡
  ├─ dialogue：角色台词
  ├─ thought：明确允许展示的内心内容
  └─ system：地点、物品、战斗等状态提示
             ↓
前端逐块播放、每块逐字显示
             ↓
播放结束 → 开放玩家输入
```

这样可以使立绘、表情、背景和状态提示精确同步，也便于存档和历史记录回放。

### 3.2 流式策略

- **当前不做真正的模型 Token 流式输出。**
- 前端逐字显示会提供连续阅读体验，且不增加模型调用。
- 后续如模型输出时间成为明显问题，可以保持同一 `NarrativeBeat` 协议，改为“确认后按播放块推送”，优先缩短第一句的等待时间。
- 客观状态（移动、战斗胜负、HP、物品）必须在 Runtime 完成结算后才能显示，不能由未完成模型文本提前宣布。

### 3.3 已确定：播放交互与记录规则

- 播放期间点击文本区只会补全当前播放块；完整显示后再次点击才进入下一块，普通点击不跳过整段剧情。
- 自动播放默认关闭；开启后在完整显示一块后短暂停留，再进入下一块。最后一块、系统提示与需要玩家确认的时刻停止自动播放。
- 快进只提高逐字速度，不省略内容、不改变播放顺序。
- 所有覆层打开时暂停播放；关闭后从同一播放位置继续。行动提交后输入锁定并保留草稿；若 Runtime 拒绝行动，恢复编辑并保留原草稿。
- 已完整播放的公开 `dialogue` 与 `narration` 才写入文本回看；重要 `system` 与 `scene_transition` 写入世界记录。临时系统提示、回合计数和被拒绝行动不进入永久记录。玩家私密想法仅可进入私记，绝不进入公共事件流、普通 LOG 或 NPC Observation。

### 3.4 已确定：第一版 NarrativeBeat 协议

每个 `NarrativeBeat` 关联一个或多个已确认事件、对应状态修订号，并包含按顺序播放的块。第一版只使用五种块：

| 类型 | 职责 | 记录去向 |
| --- | --- | --- |
| `narration` | 环境、动作、镜头与时间推进 | 文本回看 |
| `dialogue` | 已说出口的角色或玩家台词 | 文本回看 |
| `thought` | 明确允许玩家看到的内心材料 | 玩家私记（可选） |
| `system` | Runtime 已结算的客观提示 | 重要变化进入世界记录；临时提示不记录 |
| `scene_transition` | 已确认的地点或时间标题切换 | 世界记录，并以短标题进入回看 |

战斗不设独立播放块：动作与反应属于 `narration`、台词属于 `dialogue`、已结算的状态变化属于 `system`；血条和目标由独立的战斗状态层读取 `GameState.battle`。

第一版 Renderer 对已有 `GameEvent` 做确定性映射，不读取图集、不推断表情、不增加任何 AI 调用。背景仅由 `scene_transition` 更新；对话默认只高亮说话者；无明确画面数据时保持当前画面。

## 4. 已确定：地图与地点转换

地图定位为 **开放地点导航层**，不是强制线性关卡树。

### 4.1 地点状态

前端地点节点只需要表现：

| 状态 | 含义 |
| --- | --- |
| 未探明 | 玩家尚不知道地点，显示问号或不展示细节。 |
| 可前往 | 已发现且当前可到达。 |
| 受阻 | 已知但因门禁、路线、剧情状态等暂不可达。 |
| 推荐 | 不强制进入；表示当前最有价值的剧情方向。 |

一次事件可以解锁多个此前未知地点。地图资源（底图、图标、坐标）只负责视觉表现；可否进入和进入后发生什么都由 Runtime 的地点与世界状态决定。

### 4.2 主要移动方式

玩家主要通过自由输入发出地点转换请求：

```text
“我们去中央管制室。”
“回迦勒底。”
“前往刚才发现异常的桥边。”
```

地图点击是辅助入口，不替代自然语言。处理流程：

```text
地点转换指令 / 地图点击
        ↓
Pi 或确定性解析得到 destination 候选
        ↓
Runtime 检查已知性、连通性、路线与世界限制
        ↓
成功：移动事件与新场景
失败：世界内提示（未知路线、门锁、无法直接转移等）
```

### 4.3 推荐地点

“推荐”不是写死的下一关，而是由两部分共同计算：

```text
原作剧情中的地点推进参考
          +
本局已经发生的客观历史与剧情偏离
          ↓
当前推荐地点
```

因此原作地点仍可被推荐，但玩家提前取得情报、改变人物状态或偏离主线后，推荐可以自然转向新的地点；不把玩家锁死在原作路线。

## 5. 已确定：战斗的前端定位（尚未制作界面）

战斗采用 **简洁文字战斗 + 状态栏 / 血条**，不试图在 HTML 第一版复刻 FGO 的完整战斗演出。

当 `GameState.battle` 存在时，前端未来显示：

- 当前回合和战斗目标；
- 敌我 HP 条、名称、基础状态；
- 同行角色状态；
- 与主叙事页共用的统一自由输入框。

玩家输入的战斗参与方式已在后端确定：

| 方式 | 体验 |
| --- | --- |
| 具体指挥 | 输入攻击、防御、技能、物品、撤退等明确意图。 |
| 委托同行者 | 让同行从者或角色采取默认行动。 |
| 快速结算 | 玩家明确输入“尽快解决”“跳过这场战斗”等时使用。 |

战斗由剧情/GM 可信入口创建，玩家不能凭输入伪造战斗开始。前端只读取已确认的战斗状态。

## 6. 已确定：功能入口与信息架构

主叙事页面保留以下入口，具体视觉形式可后定：

```text
地图
档案
玩家面板
记录
菜单
```

### 6.1 档案

已确定的角色档案方向：

- 按“在场 / 已认识 / 线索人物”组织角色；
- 显示玩家已知的人物信息，而不是无条件展示完整 CIF 或世界真相；
- 从者可展示型月风格参数：筋力、耐久、敏捷、魔力、幸运、宝具；
- 展示技能、宝具与可见能力说明；
- 原“本局经历”栏目调整为 **对玩家的态度**；
- 同行角色可在档案中统一管理，不额外设置一个功能重复的“从者协作”入口。

### 6.2 玩家面板

玩家面板改为与开局身份无关的**角色面板**，统一使用：基础参数（筋力 / 耐久 / 敏捷 / 魔力 / 幸运 / 宝具）、身份与职阶（若有）、技能、核心能力、物品、当前状态（仅在影响行动时显示）。

- 御主可将令咒放入核心能力、魔术放入技能；英灵可将宝具放入核心能力、职阶与固有能力放入技能。
- 变身器、武器、礼装与消耗品均归物品；没有的栏目不显示，未知信息使用 `?`。
- 不设置常驻“限制”栏目；负伤、魔力不足、灵基不稳等仅在实际影响行动时作为当前状态出现。
- 它用于查看可用资源和已掌握能力，而不是替代玩家的自由输入。

### 6.3 记录与菜单

已确认需要：

- 文本回看：按实际播放顺序保存已读的公开叙事、对白与玩家发言；打开后暂停播放，关闭后原位继续。
- 存档 / 读档：存档位显示章节或地点、最近已读文本、时间；读档前二次确认，并提示未提交草稿不会保留。
- 设置：文字速度、自动播放等待、音量、显示效果与系统提示；不放世界规则或角色数据。
- 世界记录：按已确认事件、地点与主线进展整理的客观汇总，可后置实现。

具体信息层级和视觉形态尚未决定。

## 7. 美术资产与表现策略

### 7.1 背景

背景按章节或地点建立资源池，而不是每一个剧情节点单独制作背景。一章通常少量场景图即可覆盖绝大多数普通节点；关键节点再补专属图。

### 7.2 角色立绘

角色立绘绑定角色和服装/灵基状态，而非绑定地图节点。需要资产清单来映射：

```text
characterId + outfit / ascension + pose + expression
→ 对应图片资源
```

Atlas 中的角色、背景和地图资源可作为后续资源整理的参考来源；资源合法性、下载方式、实际覆盖范围仍需单独确认。

### 7.3 表情切换

目标是支持接近原作的表情切换：使用完整身体底图搭配面部差分，或先使用已切好的完整表情立绘。具体图片切分工作流、工具和资产格式 **尚未决定**，不纳入当前 MVP 的开发阻塞项。

## 8. 后端与前端边界

前端可以从 Runtime 的状态投影和事件流渲染 UI，但不应直接连接数据库。

```text
数据库
  ↓
Runtime（规则、结算、权限、状态）
  ↓
HTTP 状态投影 + SSE 事件流
  ↓
HTML 前端（表现、输入、播放）
```

这使当前 HTML 前端与未来可能的其他前端技术（游戏引擎、桌面端等）兼容：只要继续消费相同的状态和事件协议，游戏后端无需重写。

## 9. 当前已经实现与尚未实现

### 已实现的后端支撑

- 玩家可见状态投影与 SSE 游戏事件流；
- 对话、开放行动、自由输入候选解析的基础边界；
- 地点、可见场景对象、确定性移动 / 观察 / 交互；
- 角色出场的 Runtime 权限门；
- 战斗状态、可信战斗创建、三种参与方式的原型结算；
- 角色 CIF、客观事件、证据和持久化基础。

### 已存在但仅为原型的前端

- 当前 `public/` 中存在一个迦勒底终端风格的技术演示页面；
- 它用于验证 API、状态读取与事件接收，**不是本文定义的最终视觉小说主界面**。

### 尚未实现

- 文本回看（LOG）、播放进度持久化、覆层暂停恢复与读档后回放；（`NarrativeBeat` 接收、确定性 Renderer 接线、播放队列、逐字显示与点击推进第一版已完成）
- FGO / FSN 混合主叙事页；
- 播放队列、逐字显示、LOG 回放；
- 地图页面及地点发现 / 推荐的可视化；
- 档案、玩家面板、存读档与设置页面；
- 战斗血条 UI；
- 美术资源清单、加载、站位和表情差分系统；
- 真正的分块推送或模型流式优化。

## 10. 待讨论与建议顺序

| 主题 | 需要决定的内容 |
| --- | --- |
| 主叙事页细节 | PC / 移动端比例、文字框尺寸、按钮位置、自动播放与快进规则。 |
| NarrativeBeat | 播放块字段、角色站位、表情、背景切换和系统提示的正式协议。 |
| 档案页 | 信息可见性、人物分类、参数与对玩家态度的具体展示。 |
| 地图页 | 地图点击交互、推荐说明、未知地点的显示方式。 |
| 美术工作流 | Atlas 资源清单、缓存、切图、表情差分和版权边界。 |
| 存档 / 记录 | 存档槽、回放范围、世界记录与玩家私密信息的权限。 |

推荐下一步先定义 `NarrativeBeat`：它是 Runtime 事件与最终视觉小说主页面之间缺少的表现层协议，也会直接决定主页面、LOG 和存档回放如何实现。
