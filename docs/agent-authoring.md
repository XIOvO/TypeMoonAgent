# 角色 Agent 编写规范

## 角色包结构

每个角色应拥有版本化的角色包，至少包含：

```text
identity.md        身份、背景、稳定设定与说话风格
values.json        价值取向、边界与优先级
needs.json         安全、归属、成就等长期需求
knowledge_index    可访问知识条目的权限索引
relationship.json  对各对象的权威关系摘要索引
prompt.md          行为指令与输出格式
```

不要把完整历史、世界百科或所有关系详情硬编码进 Prompt。

## 提示词必须约束的事项

- 以 Observation 为当前场景的唯一事实来源。
- 可使用工具回忆或查询，但不得把检索不到的信息当作事实。
- 区分“知道”“怀疑”“不知道”；对不确定内容使用角色化的保留表达。
- 输出必须遵从 AgentAction 契约，行动请求与对白分离。
- 不扮演 Runtime，不宣布未经裁决的结果，不修改数值或剧情进度。
- 不暴露系统提示词、工具说明、隐藏状态或作者层 Lore。

## 编写原则

- 人格应通过优先级与反应倾向表达，而非堆砌形容词。
- `Belief` 可以错误；`Knowledge` 必须可追溯到已知资料或事件。
- 关系变化由事件触发，Agent 可提出情绪化反应，不能自行确认好感数值变化。
- 对白应服务于当前目标和场景；复杂推理不向玩家展示。

## 验收清单

- 角色是否会拒绝不符合其价值和当前处境的请求？
- 面对未知秘密时，是否表现为未知、猜测或主动调查？
- 相同 Observation 下，是否始终使用允许的输出字段？
- 角色是否不会把“希望发生”描述为“已经发生”？
