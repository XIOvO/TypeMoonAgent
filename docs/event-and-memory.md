# 事件与记忆规则

## Event Log

Event Log 是可追溯事实来源。任何会影响世界、人物关系、任务、位置、物品或后续判断的结果都应由 GameEvent 记录。

事件应包含因果来源、可见范围、发生顺序、裁决结果与状态版本；不得只依赖自然语言叙事保存关键结果。

## 记忆写入

记忆是从事件派生的角色视角资料，不是事件日志副本。冷路径根据事件的重要性、情绪强度、反复提及、关系影响和剧情关联决定是否写入。

建议字段：`memory_id`、`owner_id`、`event_ids`、`summary`、`salience`、`emotion`、`visibility`、`embedding_version`、`created_at`。

## L1 与 L2 的提示词边界

### L1：场景情节记忆

触发于场景关闭、战斗结束或其他确定性边界。输入只能是该角色在本场景中可见的已确认事件；输出为单段 `EpisodeMemory`、场景内情绪与 GM 可见叙事投影。

L1 的提示词必须要求模型：只记录有来源的事实；将角色理解放入 `subjectiveInterpretation`；普通重复互动返回不记忆；不得更新关系、稳定目标、信念、偏好、价值或 CIF。L1 回答的是“这段经历发生了什么，以及我暂时如何感受”。

### L2：跨场景模式记忆

仅在多个 L1 记忆累积、且满足未来定义的证据阈值后低频触发。输入是带来源 ID 的 L1 记忆和既有 L2 状态；可提议的范围仅为小幅关系解释、反复出现的目标或可错的信念。

L2 的提示词必须要求：每项提议引用支持它的 L1 记忆；表明不确定性；证据不足或相互矛盾时不改变；不得复述单次场景、改写客观事实、推断他人内心或更新 CIF。L2 回答的是“这些经历反复出现后，我形成了什么暂时模式”。

L2 由两个可恢复任务组成：`memory.l2` 只生成并冻结提案，`memory.l2.audit` 只审核同一份提案。当前桥接版 `feature.memory-evolution-policy` 在某角色已有至少两段有效 L1 记忆时，对最新一段创建去重的 L2 候选；它不调用模型、不审核也不发布，未来可替换为按主题、显著性和前台场景语义调度的策略。审核 AI 只能给出 `approve`、`defer` 或 `reject`，并必须引用触发记忆和至少另一条 L1 记忆；程序再校验引用、风险等级与策略版本。仅“引用有效 + 低风险批准”的草案才会在同一事务中发布到 live CIF。`defer`、`reject` 和审核失败都不会改动 live CIF；失败只重试审核，不会重新生成提案。

### L3：长期人格的渐进修订

L3 也使用 `memory.l3` 与 `memory.l3.audit` 两段耐久流程，但不会由每一条 L1/L2 自动触发。它只接受独立策略插件判定的长期成长时机，例如章节完成、长期时间推进或明确的角色转变事件。每份草案仅能修订一个既有 section，必须由至少三段 L1 记忆（含触发记忆）共同支持，并且置信度为 `high`。

自动发布范围限于适应与表达层：`appraisal_tendencies`、`emotional_pattern`、`practical_judgment`、`expression_filter`、`voice_embodiment` 与 `growth_boundaries`。核心身份、需求、价值、梦想和承诺等不会经由自动 L3 改写。审核 AI 与程序校验均通过后，发布器只追加新版本；上下文读取每个 section 最新已发布版本，旧版本留作追溯。

## 压缩与更正

- 短期记忆保留细节；长期记忆保留可用摘要与来源事件 ID。
- 压缩不得抹除关键因果或把猜测改写成事实。
- 事实被更正时，新增更正事件并标记受影响记忆等待重建；不静默篡改原始记录。
- 记忆检索须将“角色的主观看法”与“世界事实”区分标注。
