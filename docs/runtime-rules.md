# Game Runtime 规则

## 权威边界

Runtime 是以下内容的唯一写入者：世界时间、位置、物品、数值、任务、战斗结果、可见性、剧情解锁与角色关系的权威值。Agent、前端和后台任务只能提交请求或派生数据。

## 每轮处理顺序

1. 验证玩家身份、会话、输入格式与频率限制。
2. 读取当前权威状态，检查行动前置条件。
3. 为受影响角色构造最小 Observation。
4. 调用相关 Agent，或在无需 Agent 时使用确定性规则。
5. 校验 AgentAction 的 actor、目标、动作类型和参数。
6. 在同一事务中裁决结果、更新状态、追加 GameEvent、递增 revision。
7. 将可见事件推送给前端，并向冷路径投递事件。

## 裁决规则

- Agent 对事实的叙述不是事实；只有 Runtime 的裁决事件才能改变权威状态。
- 行动不合法时返回结构化失败事件，例如 `action_rejected`，并提供面向玩家的原因。
- 多角色对同一资源冲突时，以事件序列、明确的规则优先级和确定性随机种子裁决。
- Runtime 可接受角色的自然语言对白，但不能把其中的未经验证声明写入 WorldState。
- 任一 Agent 超时、格式错误或工具失败时，保留世界状态并生成可恢复的失败结果；不得猜测性写入。

## 并发与幂等

- 每个 PlayerAction 必须携带唯一 ID；重复提交返回第一次的结果。
- 写入前校验 `state_revision` 或使用事务锁，防止两个行动覆盖同一状态。
- 所有随机判定写入 `seed`、公式和结果，保证回放可复现。

## 禁止事项

- 不以客户端提供的地点、背包或数值作为可信事实。
- 不让 Agent 直接执行数据库写入。
- 不因叙事文本“听起来合理”而跳过规则校验。
