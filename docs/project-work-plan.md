# 项目工作计划与优先级

> 本文将“已完成的基础能力”“已定但尚未实现的设计”与“尚未决定的事项”分开管理。它是当前开发顺序的工作清单，不替代 [整体架构](project-overview.md)、[当前实现状态](current-status.md) 或 [前端设计方案](frontend-design-plan.md)。

## 1. 项目目标与边界

目标是完成一款 **PC 优先、单人本地游玩、以视觉小说阅读与自由输入为核心的 Fate 风格 Agent Game**。

- `GameRuntime` 是唯一的世界裁判；前端、Pi Agent 与 CIF 均不能直接确认或改写世界事实。
- Pi Agent 仅用于已有的角色回应、必要的自由输入解释与低频 CIF 草案；表情、镜头、逐字播放、地图展示和记录均不得增加额外 AI 调用。
- 当前以可运行的“冬木 / 迦勒底”垂直切片为目标，不以全量原作、完整 FGO 战斗演出、移动端或离线模型为前置条件。

## 2. 当前基线

| 状态 | 内容 |
| --- | --- |

## 3. 工作包与完成条件

### P0：设计与契约同步（进行中）

**目标：** 让文档、协议和实现状态一致，避免“方案已讨论”被误认为“功能已完成”。

- 维护 `frontend-design-plan.md`：已确定的交互规则进入文档；未讨论的视觉与资源细节保持待定。
- 维护 `current-status.md`：反映 `NarrativeBeat` 与确定性 Renderer 已完成，但尚未接入浏览器。
- 为新增协议编写类型与确定性测试。

**完成条件：** 文档不再把已完成 Renderer 标为未实现；后续工作都能在本计划中定位到工作包。

### P1：主叙事垂直切片（最小闭环已完成）

**目标：** 让当前已结算的对话、移动、观察和系统事件能以视觉小说方式完成一次“播放 → 输入 → 再播放”的闭环。

- 将确定性 Renderer 接入 SSE 或等价的浏览器事件通道；浏览器消费 `NarrativeBeat`，不再直接将 `GameEvent` 作为终端日志显示。
- 实现浏览器播放队列：逐字显示、点击补全当前块、再次点击进入下一块、播放结束后开放输入。
- 实现暂停语义：任何覆层打开即暂停，关闭后从同一块、同一字符位置继续。
- 实现行动草稿规则：提交中锁定；被 Runtime 拒绝时恢复编辑且保留草稿。
- 使用中性占位背景和立绘框即可；不等待表情图谱或最终视觉设计。

**依赖：** 已完成的 `NarrativeBeat` 与 Renderer。

**完成条件：** 演示玛修的一次对话能在正式主舞台播放；移动、观察与拒绝行动分别按既定记录规则显示；全程零额外 AI 调用。

### P2：文本回看、菜单与播放恢复（最小版本已完成）

**目标：** 建立 Galgame 式“已读内容”体验，而非技术事件日志。

- 保存已完成播放的公开 `dialogue`、`narration` 与必要的转场标题。
- 实现文本回看覆层；打开时暂停播放，关闭后恢复。
- 实现设置的最小集合：文字速度、自动播放等待、系统提示显示。
- 设计并实现播放进度、已读内容、输入草稿的本地/存档数据结构。

**依赖：** P1。

**完成条件：** 刷新或重新打开回看不会重复写入记录；未完整播放的内容不会被提前记录。

### P3：地图与地点信息层

**目标：** 让玩家查看已知地点并辅助提出移动请求，但不绕过自由输入和 Runtime。

- 在玩家可见状态中增加地点发现、受阻理由、推荐与当前所在地的投影字段。
- 实现地图覆层及五种地点状态：当前所在地、可前往、推荐、受阻、未探明。
- 点击地点只预填行动文本；实际移动仍交由输入解析与 Runtime 确认。
- 后续接入路线、章节地图资源与推荐原因。

**依赖：** P1；地点发现/推荐的 Runtime 投影。

**完成条件：** 不能通过地图绕过可达性校验；受阻和未知地点不泄露隐藏信息。

### P4：档案与角色面板

**目标：** 把玩家已知的人物和自身资源整理为叙事辅助信息，而非后台数据库。

- 档案：在场 / 已认识 / 线索人物；身份、对玩家态度、行动相关能力与已公开从者信息。
- 角色面板：参数、身份/职阶、技能、核心能力、物品、仅在影响行动时出现的当前状态。
- 建立玩家可见的投影契约；不得暴露 CIF 原始字段、NPC 私密状态或尚未确认的设定。
- 所有不存在的栏目隐藏，未知内容显示 `?`，不以空槽暗示秘密。

**依赖：** P1；各类玩家可见数据的 Runtime 归属与投影。

**完成条件：** 御主、英灵、误入者等身份可使用同一面板结构；打开页面不改变任何世界状态。

### P5：存档、读档与世界记录

**目标：** 完成单机游戏必需的存档生命周期。

- 明确存档快照中包含：World State、事件、CIF、已读 NarrativeBeat、播放进度和必要的本地设置。
- 实现手动存档、自动存档与读档；读档前确认并告知未提交草稿将丢失。
- 实现世界记录：按已确认地点、事件与主线进展汇总；区别于文本回看。
- 补 migration 与重启后的幂等恢复测试。

**依赖：** P2；当前 SQLite 持久化基础。

**完成条件：** 读档后世界、回看和播放位置保持一致；不会将玩家私记或隐藏信息混入公开记录。

### P6：自由行动与战斗状态层

**目标：** 让自由输入不仅能对话，还能在明确规则下影响地点、对象和能力；战斗保持叙事主导。

- 实现 `ActionResolver`：行动候选在地点、对象、角色能力与可见性约束下结算为确定性事件。
- 增加物品与能力的 Runtime 规则，而非让模型直接宣布成功。
- 实现仅在 `GameState.battle` 存在时显示的战斗状态层：目标、HP、状态、统一输入。
- 不增加独立战斗播放块；动作属叙事、台词属对白、已结算变化属系统提示。

**依赖：** P1；玩家能力与物品的最小数据模型。

**完成条件：** 任意成功或失败行动均可追溯到事件；战斗状态不要求复刻 FGO 演出。

### P7：章节推进与内容循环

**目标：** 让冬木章节能在玩家偏离原作后仍按因果自然推进。

- 为当前章节定义少量 `CanonBeat`、`WorldBranch`、地点与触发条件。
- 接入角色可用性、剧情压力与 Runtime 受控引入。
- 扩展 Lore 检索、说话者映射和必要的 CIF 冷路径整合。
- 为每个章节建立最小可玩验收场景，而不是一次性结构化全量原作。

**依赖：** P3、P6；已有 Story Director 与 Lore 基础。

**完成条件：** 玩家可触发、偏离并回到可理解的章节因果链；角色不会因资料库内容自动越权出现。

### P8：资源、视觉语言与交付（后置）

**目标：** 在可玩闭环稳定后，补足品质与单机发行能力。

- 视觉设计：色彩、字体、布局、名牌、动效、音频与 PC 页面细节。
- 资源 manifest：背景、立绘、站位、服装、表情图谱、加载与缺失回退。
- 继续完善表情标注实验工具；它不应阻塞 P1–P7。
- 全量本地资源、桌面/安装包封装、备份、移动端或本地模型作为后续独立项目。

**依赖：** P1–P5 的稳定交互与存档格式。

**完成条件：** 资源系统不改变 Runtime 权威边界；可在没有网络时加载本地内容（模型调用策略另行决定）。

## 4. 推荐执行顺序

```text
P0 文档同步
  → P1 主叙事垂直切片
  → P2 文本回看与播放恢复
  → P3 地图 + P4 档案/角色面板（可并行）
  → P5 存档/读档
  → P6 自由行动与战斗状态层
  → P7 章节推进
  → P8 资源、视觉与交付
```

**下一项实际工作：P3 与 P4。** P2 已完成浏览器本地的文本回看、播放位置与草稿恢复，以及文字速度、自动播放、系统提示显示等最小设置。接下来可并行补地图的玩家可见投影，以及档案/角色面板的数据投影；两者都不依赖最终美术。

## 5. 每个工作包的通用验收

- 仅以 Runtime 已确认事件和玩家可见状态作为前端事实来源。
- 不新增为表情、镜头、播放或信息展示服务的 AI 调用。
- 每项规则同时覆盖成功、拒绝、断线/刷新或回放中的至少一种边界情况。
- 新协议有类型与测试；新 Runtime 行为有确定性测试；不引入绕过事件记录或可见性过滤的写入路径。
- 文档状态在合并实现后同步更新。
