# 检索与信息权限策略

## 数据分层

| 层 | 用途 | 默认可见者 |
| --- | --- | --- |
| Lore | 作者层世界设定与规则 | Runtime / 导演工具 |
| Knowledge | 已知的客观资料 | 被授权的角色 |
| Memory | 个体经历与互动历史 | 该角色本人 |

每个条目必须带有 `source`、`visibility`、`owner_id`（如适用）、`unlock_conditions`、`created_at` 与 `confidence`。

## 查询规则

- 默认不检索；只有当前行动确实需要知识、回忆或关系细节时才调用。
- 返回 3–5 条最相关结果，附带来源、时间与置信度；不返回整篇资料。
- 先做权限过滤，再做语义检索和重排。绝不可先检索后仅依赖模型自行“忽略秘密”。
- 检索结果进入上下文前需限制长度并去重。
- 未命中时明确返回“无可用资料”，Agent 应表现为不确定而非编造。

## 隔离要求

- Lore 的真相不能自动复制到 Character Knowledge。
- 角色 A 的私密 Memory 不可被角色 B 查询，除非存在共享事件或明确的叙事授权。
- 玩家已知不等于所有角色已知；角色已知也不等于玩家 UI 可显示。
